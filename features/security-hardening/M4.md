# M4: Bounded metadata storage

Status: planned; not started

## Goal

Account for torrent metadata independently of media jobs and keep managed metadata within validated budgets.

## Why and evidence

M0 observed persisted torrent metadata outside a tiny media-only budget. Manual download deletion is implemented separately and does not establish automatic metadata budgeting.

Detailed rationale: [security design](SECURITY_PLAN.md). Primary evidence: [M0_EVIDENCE.md](M0_EVIDENCE.md); additional record: [SECURITY_PLAN.md](SECURITY_PLAN.md). These historical reports can contain earlier pending results; the explicit final outcome here is the current acceptance summary.

## Scope

This milestone only. Preserve tokens, signed descriptors, saved state and playback contracts unless the milestone design explicitly requires a compatible revision. Other security milestones and deferred dashboard layout are excluded.

## Acceptance criteria

- [ ] AC1: Account for existing metadata at startup with byte/count limits separate from media capacity.
- [ ] AC2: Use concurrency-safe atomic reservations and bound all metadata-write paths, including peer metadata.
- [ ] AC3: Evict only eligible managed entries while preserving active/resumable jobs, safe paths and restart reconciliation.
- [ ] AC4: Expose protected usage/limits and pass offline/resume/storage checkpoint C4.
