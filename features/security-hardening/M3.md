# M3: Bounded upstream processing

Status: planned; not started

## Goal

Bound addon response processing, stream counts, active work and queues without stopping intentional background downloads.

## Why and evidence

M0 accepted an oversized in-memory response/many streams and observed concurrent metadata fan-out. Those measurements did not demonstrate a host exhaustion event.

Detailed rationale: [security design](SECURITY_PLAN.md). Primary evidence: [M0_EVIDENCE.md](M0_EVIDENCE.md); additional record: [SECURITY_PLAN.md](SECURITY_PLAN.md). These historical reports can contain earlier pending results; the explicit final outcome here is the current acceptance summary.

## Scope

This milestone only. Preserve tokens, signed descriptors, saved state and playback contracts unless the milestone design explicitly requires a compatible revision. Other security milestones and deferred dashboard layout are excluded.

## Acceptance criteria

- [ ] AC1: Bound decoded JSON bytes, stream counts and expensive descriptor inputs, including account-sync responses.
- [ ] AC2: Bound active metadata fetches, pending metadata queue and concurrent stream-list admission; validate configured limits.
- [ ] AC3: Release permits/cancel lookup work on failure, timeout and disconnect without cancelling established media downloads.
- [ ] AC4: Measure bounds/responsiveness under synthetic load and pass checkpoint C3 with normal playback.
